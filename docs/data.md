# Data and migrations

## Ownership

Each service owns its schema. There are no cross-service joins and no shared
database user. A service that needs another service's data stores a reference
and resolves it over HTTP.

| Service | Schema | Notable tables |
| --- | --- | --- |
| catalog | catalog | product, product_variant, price_book, discount_rule |
| inventory | inventory | stock_item, reservation, warehouse, lot |
| order | orders | orders, order_line, cart, return_request |
| payment | payments | payment, refund, ledger, settlement |
| customer | customers | customer, address, consent, loyalty_account |
| shipping | shipping | carrier, delivery, manifest, shipping_label |
| notification | notifications | message, template, campaign, webhook |

## Schema management

Production schemas are managed by versioned migrations. The application never
runs `hibernate.hbm2ddl.auto=update` outside local development. Local H2 runs
may create tables from the entities for convenience.

Migration rules:

1. One logical change per migration.
2. Migrations are forward-only. A mistake is corrected by a new migration.
3. A migration must be safe to run while the previous application version is
   still serving traffic.
4. Never rename a column directly. Add the new column, backfill, switch reads,
   then drop the old column in a later release.
5. Never drop a column in the same release that stops writing it.
6. Every new table gets a primary key, a unique natural key where applicable,
   and an index for each query used by a controller.

## Naming

| Object | Convention | Example |
| --- | --- | --- |
| Table | snake_case, singular | `product_variant` |
| Column | snake_case | `created_at` |
| Primary key | `id` | `id` |
| Natural key | `code` | `code` |
| Foreign reference | `<thing>_ref` | `order_ref` |
| Boolean | positive adjective | `active`, `picked`, `settled` |
| Timestamp | past participle | `created_at`, `settled_at` |

## Standard columns

Every mutable entity has:

```sql
id          bigint generated by default as identity primary key,
code        varchar(40) not null unique,
name        varchar(160) not null,
status      varchar(20) not null,
priority    integer not null,
amount      numeric(14, 2),
version     bigint not null,
created_at  timestamp with time zone,
updated_at  timestamp with time zone
```

`version` supports optimistic locking. A conflicting update fails rather than
overwriting another writer.

## Money

Money is stored as `numeric(14, 2)`, never as a floating-point type. The
currency is either implied by the service or stored beside the amount. Do not
sum amounts in different currencies; convert first with a recorded rate.

## Dates and time

- Store `Instant` / `timestamp with time zone`.
- Render ISO-8601 with `Z`.
- Business days are computed in UTC unless a document says otherwise.
- Never store a local time without its zone.

## Retention

| Data | Retention | Notes |
| --- | --- | --- |
| Orders and invoices | 7 years | Legal and tax |
| Payments and ledger | 7 years | Financial audit |
| Refunds and chargebacks | 7 years | Financial audit |
| Customer account | Until deletion request + 30 days | Then anonymise |
| Consent records | Life of account + 7 years | Proof of consent |
| Support tickets | 2 years | Then anonymise |
| Notification events | 90 days | Operational only |
| Application logs | 30 days | No PII |
| Tracking events | 1 year | Customer service |

Deletion requests anonymise the customer and keep the financial records that
must be retained. Anonymisation replaces direct identifiers and keeps an
opaque key so orders remain linkable.

## Backups

- Full backup daily, retained 30 days.
- Point-in-time recovery for the last 7 days.
- Restore is tested quarterly.
- A restore test records the time to recovery and any missing data.

## Data quality checks

Scheduled checks look for:

- rows with a blank natural key
- duplicate natural keys
- negative quantities or amounts where the domain forbids them
- archived rows that still receive writes
- ledger entries that do not balance
- reservations older than their expiry with no release

Findings are reported, not auto-corrected, unless the correction is trivial
and reversible.
